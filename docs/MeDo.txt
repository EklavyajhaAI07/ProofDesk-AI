In hackathons, a small working MVP usually beats a big half-finished platform, because judges care about execution, ease of use, impact, and a clear demo of core functionality. Since the MeDo hackathon explicitly asks for a live app and explains projects through how MeDo generated useful parts, your best move is to build one narrow, magical workflow that works reliably from input to result.

For ProofDesk, the strongest MVP is not “document workspace for everything.” It is: upload one document, extract action items, show due dates, and generate one ready-to-use draft. That is small enough to finish, clear enough to demo, and smart enough to feel impressive.

MVP scope
The cleanest version of ProofDesk should solve one painful problem: people receive messy PDF instructions, screenshots, or copied messages, but they do not know what action to take next. Your MVP should take one input, process it with AI, and return three outputs only: summary, tasks with deadlines, and one draft response.

Core features
Build only these 4 features:

File or text input: upload PDF/image or paste message text.

AI extraction: generate short summary plus task list with due dates and priority.

Action board: show extracted tasks in a simple checklist/table UI.

Draft generator: create one reply draft such as email or WhatsApp follow-up. with the one tap butten "SEND" Feature

Skip for hackathon
Do not build these now:

Team collaboration

Real-time notifications

OCR pipeline complexity beyond one simple parser

Calendar integrations

Role-based permissions

Large analytics dashboard

Those features increase risk without improving your core demo much.

Best “crazy but small” moment
Your one standout feature should be:

“Drop a messy client PDF or screenshot, and ProofDesk instantly turns it into:

what this is about,

what you must do,

when to do it,

what to reply.”

That is memorable because it converts confusion into action in one shot, which fits common hackathon judging around originality, implementation, user experience, and impact.

Backend and APIs
The backend should be thin and workflow-based, not enterprise-style. Because MeDo is positioned for building full-stack apps with backend logic and databases quickly, keep your API design very simple and visible.

Recommended backend modules
File ingestion

Text extraction

AI processing

Data persistence

Result retrieval

Minimal API set
Use only these endpoints:

POST /documents/upload
Receives file or text input and creates a document record.

POST /documents/:id/process
Runs extraction pipeline, AI summary, task extraction, and draft generation.

GET /documents/:id
Returns one processed document with outputs.

GET /documents
Returns all saved documents for history page.

PATCH /tasks/:id
Optional, only if you want to toggle task status like open/done.

That is enough for a real full-stack MVP.

Internal backend pipeline
Inside /process, do this:

Get document text.

Send text to AI prompt.

Ask for strict JSON output:

summary

tasks]

draft_reply

Validate JSON.

Save response to DB.

Return processed result to frontend.

This is safer than asking AI for free-form text and then parsing later. It reduces demo risk.

App data flow
This should be your simplest full-stack story in the presentation.

User flow
User uploads a PDF/image or pastes text.

Frontend sends it to backend.

Backend extracts text from the input.

Backend sends clean text to AI with structured prompt.

AI returns summary, tasks, due dates, and one draft reply.

Backend saves everything in DB.

Frontend shows summary, task list, and draft.

User marks a task done or opens older document from history.

In short
Input → extract text → AI structure → save → show action items

That is the whole product. Clear, full-stack, and demo-friendly.

System design thinking
Think like this:

Problem
Unstructured documents create mental overload. Users waste time reading, re-reading, and figuring out what action is needed.

Product promise
ProofDesk converts unstructured input into immediate next actions.

MVP principle
Do one workflow extremely well:

One input

One AI pass

Three outputs

One simple saved history

Technical design principle
Use deterministic app flow around a flexible AI core.

Deterministic parts: upload, save, fetch, render, task toggle

AI part: summary/task/draft generation

This makes the app feel reliable even though AI is involved.

AI prompt design
Your prompt should instruct the model:

Read the document carefully

Extract only explicit or strongly implied action items

Identify due dates

Mark priority

Write a short professional reply draft

Return strict JSON only

This is one of the most important engineering decisions in the MVP, because clean AI output makes the whole app stable.
